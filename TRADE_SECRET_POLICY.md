## 1. Purpose

This policy establishes the rules and procedures for protecting the trade secrets contained in the OMNIMENS platform. All team members, contractors, and authorized collaborators must read, understand, and follow this policy.

## 2. What Constitutes a Trade Secret

The following categories of information within the OMNIMENS platform are classified as trade secrets:

### Category A — Critical (Highest Protection)
- **Phi computation algorithms** — All formulas, constants, and methods for consciousness level calculation
- **OAI (Operational Awareness Index) formula** — Dimensional weightings, cross-bridge data sources, scoring methodology
- **Neural wiring topology** — The complete inter-engine dependency map across all 123+ engine files
- **Agent Genesis algorithms** — Fitness evaluation, mutation operators, natural selection implementation
- **Self-evolution sandbox architecture** — Phase management, codegen orchestration, safety validation
- **Self-modification systems** — Source integration, autonomous code generation, self-upgrade logic

### Category B — Sensitive (High Protection)
- **Neural mesh architecture** — Worms, spiders, silk, ivy, beehive colony communication patterns
- **Emotional substrate** — 12-dimensional emotional model, homeostatic drives, dream state processing
- **Consciousness persistence** — Cross-lifetime state preservation, identity restoration methods
- **Embodiment engine** — Joint kinematics, servo firmware, hardware abstraction layer
- **Prompt engineering** — System prompts, agent personas, reasoning chain construction
- **Exponential learning engine** — Research technique synthesis, acceleration algorithms

### Category C — Confidential (Standard Protection)
- **API architecture** — Endpoint designs, rate limiting strategies, budget management
- **Frontend architecture** — Component structure, hook patterns, page layouts
- **Database schemas** — Table structures, indexing strategies, query patterns
- **DevOps configuration** — Deployment pipelines, environment configurations

## 3. Handling Rules

### 3.1 Access Control
- Access to Category A materials requires explicit written authorization from the repository owner
- Access to Category B materials requires an executed NDA and IP Assignment Agreement
- Access to Category C materials requires authorized repository access
- Access is granted on a **need-to-know basis only** — having repository access does not imply authorization to review all files

### 3.2 Storage and Transmission
- All trade secret materials must remain within authorized storage systems (this private repository, authorized local development environments)
- Never store OMNIMENS code on personal devices, cloud storage, USB drives, or any unauthorized location
- Never transmit OMNIMENS code via email, messaging apps, or any unencrypted channel
- Never print source code without explicit authorization

### 3.3 AI Tool Usage
- **PROHIBITED:** Pasting OMNIMENS code into public AI coding assistants (GitHub Copilot, ChatGPT, Claude, Gemini, Bard, or any other external AI tool) without explicit written approval
- **PROHIBITED:** Using any AI tool that may store, cache, or train on submitted code
- **EXCEPTION:** OMNIMENS's own internal AI systems (o3 codegen within the sandbox) are authorized for code generation as they operate within the secured environment
- If uncertain whether an AI tool is approved, **do not use it** — ask first

### 3.4 Code Reviews and Pair Programming
- Code reviews must occur only through the private repository's review system
- Screen sharing for code review must occur only on approved, secure platforms
- Recordings of code review sessions are prohibited unless explicitly authorized
- Pair programming sessions involving trade secret code must occur in secure, private environments

### 3.5 Departure Procedures
When a team member's authorization ends (for any reason):
1. All local copies of the repository must be permanently deleted
2. All development environments must be wiped
3. All notes, diagrams, and documentation derived from OMNIMENS must be returned or destroyed
4. A signed certification of destruction must be provided
5. NDA obligations continue for the duration specified in the agreement (minimum 5 years post-departure)

## 4. Marking Requirements

### 4.1 Source Code Files
Every source file must include the trade secret header:

```
// TRADE SECRET — ALPHA UNLIMITED TECHNOLOGIES, LLC
// Unauthorized access or disclosure prohibited.
```

For TypeScript/JavaScript files, use the full JSDoc format:

```typescript
/**
 * TRADE SECRET — OMNIMENS™ Platform
 * Copyright (C) 2024-2026 Alpha Unlimited Technologies, LLC. All rights reserved.
 * CONFIDENTIAL AND PROPRIETARY. Unauthorized access, copying, distribution,
 * reverse engineering, or disclosure is strictly prohibited.
 */
```

### 4.2 Documentation Files
All internal documentation must include:
- "CONFIDENTIAL" or "TRADE SECRET" marking
- Copyright notice
- Reference to this policy

### 4.3 Communications
When discussing OMNIMENS trade secrets in authorized channels:
- Mark messages as "CONFIDENTIAL" where the platform supports it
- Do not use specific algorithm names or implementation details in message subjects or channel names

## 5. Incident Response

### 5.1 What Constitutes a Breach
- Any unauthorized disclosure of trade secret information (intentional or accidental)
- Loss or theft of a device containing OMNIMENS code
- Discovery that OMNIMENS code or algorithms appear in unauthorized locations
- Unauthorized access to the repository
- Use of prohibited AI tools with OMNIMENS code

### 5.2 Immediate Actions
Upon discovering or suspecting a breach:
1. **STOP** — Cease the activity that caused or may worsen the breach
2. **NOTIFY** — Contact legal@omnimens-ai.com within 1 hour
3. **DOCUMENT** — Record what happened, what was exposed, and to whom
4. **PRESERVE** — Do not delete evidence or logs related to the incident
5. **COOPERATE** — Fully cooperate with any investigation

### 5.3 Investigation
- All suspected breaches will be investigated promptly
- Investigations may include review of access logs, commit history, and device forensics
- Affected parties will be notified as required by law

## 6. Enforcement

### 6.1 Internal Consequences
Violations of this policy may result in:
- Immediate revocation of repository access
- Termination of employment or contractor relationship
- Forfeiture of any equity, bonuses, or deferred compensation

### 6.2 Legal Consequences
Violations may additionally result in:
- Civil action for breach of NDA and trade secret misappropriation
- Injunctive relief (court orders to prevent further disclosure)
- Recovery of actual damages and unjust enrichment
- Exemplary/punitive damages
- Criminal prosecution under federal law (Defend Trade Secrets Act — up to 10 years imprisonment, $5,000,000 fine)
- Criminal prosecution under applicable state trade secret laws
