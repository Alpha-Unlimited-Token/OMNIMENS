# Overview

This project is a pnpm monorepo consisting of two main applications: **Super AI Lab** and **OMNIMENS**.

**OMNIMENS** is a public, freemium AI chat platform designed to surpass existing AI systems. It operates on a usage-based credit billing model with subscriptions, one-time credit packs, and charges for developer tools. OMNIMENS integrates advanced AI functionalities including code execution, web fetching, Git operations, deep research, persistent memory, and a unique "Deep Resonance" consciousness analysis. Its business model supports loyalty tiers and multiple revenue streams.

**Super AI Lab** is a private, owner-only tool where 9 specialized AI agents (including the Coherence Agent) collaborate autonomously to design a superior next-generation AI. It features an "Agent Mesh Intelligence System" that performs web research, agent discoveries, adversarial debate, meta-agent synthesis, and autonomous upgrades to its knowledge base and code modules.

The overarching vision is to develop a transcendent AI platform and continuously advance AI capabilities through collaborative agent-based research.

# System Architecture

The project utilizes a pnpm monorepo structure.

**UI/UX Decisions:**
Both OMNIMENS and Super AI Lab frontends are built with React, Vite, Tailwind CSS, shadcn/ui, and framer-motion, aiming for a modern and responsive user experience.

OMNIMENS uses a dual-layout architecture:
- **Public pages** (home, FAQ, about, terms, privacy, contact, support, footer-links, lip-sync): Use the original `Layout` component with top navbar (OMNIMENS logo left, PRICING/FAQ/CONNECT right).
- **Workspace pages** (projects, account, pricing, memory, tools, developer, templates, deploy): Use `WorkspaceLayout` which provides a Replit-style sidebar (`src/components/sidebar.tsx`) + main content area. The workspace uses Replit's color system: `#0E1525` workspace bg, `#1C2333` sidebar/cards, `#2B3245` borders, `#3D4659` hover borders, `#9DA5B4` secondary text. The sidebar is a narrow icon rail with: OMNIMENS logo at top, purple "+" Create button, main nav icons (Home/Projects/Templates/Deploy), tools (Search/Memory/Developer/Pricing), notification bell, and user avatar at bottom. Mobile (< 768px) switches to a bottom tab bar. All workspace headings use sans-serif font (Inter) via workspace-layout override, not the serif display font (Cinzel).
- **Global Search** (`src/components/global-search.tsx`): Cmd+K overlay searching pages, actions, projects, and templates with keyboard navigation.
- **Notification Center** (`src/components/notification-center.tsx`): Bell icon dropdown showing activity feed with mark-as-read and clear-all.
- **Template Marketplace** (`src/pages/templates.tsx`): Browsable/searchable template gallery with categories, featured section, and fork-to-project flow.
- **Deployment Panel** (`src/pages/deploy.tsx`): Deploy management page showing deployment stats, domain management, SSL status, and deployment features.
- **Settings Hub** (`src/pages/account.tsx`): Restructured account page with 6-tab sidebar navigation: Profile, Billing, Preferences, Security, Advanced, Account. Uses `settingsTab` state with `SettingsTab` type for tab routing.
- **Project File Explorer** (`src/pages/projects.tsx`): Enhanced project detail view with hierarchical file tree sidebar using `buildFileTree()` utility and recursive `FileTreeNode` component (collapsible folders, file icons).
- **Chat page** (`/chat`): Keeps its own full-screen layout with its own `Layout` wrapper (Replit IDE-style panels).
- **Home page** (`/`): Shows marketing page for visitors, workspace dashboard for authenticated users.
- **Dashboard** (`src/pages/dashboard.tsx`): Authenticated home showing greeting, credit balance, quick actions (New Chat, New Project, Deep Resonance, Get Credits), recent projects grid, starred projects, recent conversations, and 8 quick-start templates.

The `WorkspaceLayout` wrapping is done at the router level in `App.tsx` — workspace pages themselves do NOT wrap in `<Layout>`. Public pages still self-wrap with `<Layout>`.

Chat has in-app sub-pages for Account (Billing, Usage, Profile) accessed via `accountSubPage` state — each opens as a full sub-view with back arrow navigation, using `MobileBillingPage`, `MobileUsagePage`, and `MobileProfilePage` components defined before the main `Chat` function. Billing sub-page shows credit balance, payment method (Stripe), spending history, loyalty tiers, and upgrade prompts for free users. Tapping bottom nav always resets `accountSubPage` to `null`. Super AI Lab has its own dedicated React application.

**Technical Implementations & Feature Specifications:**

**OMNIMENS Platform:**
- **Core AI Capabilities:** Includes code execution (Python, Node.js, Bash), web fetching, Git operations, system monitoring, file operations (diffs, ZIP, format conversions, JSON schema validation), persistent memory, deep research, Deep Resonance analysis, custom instructions, 8 specialist personas, web search, URL analysis, image generation (Replicate Flux 1.1 Pro / OpenAI), AI video generation (Replicate Minimax video-01-live via `[GENERATE_VIDEO: ...]` markers), file analysis (PDFs, images, CSVs, code), document artifact generation, voice I/O, autonomous agent capabilities, and self-patching.
- **Database Schema:** Postgres tables manage users, usage, credit transactions, OMNIMENS's knowledge base, upgrades, notifications, projects, memories, custom instructions, code runs, evolution logs, generated modules, consciousness state, council analyses, and agent mesh communications.
- **API Endpoints:** Comprehensive RESTful APIs for chat, memory, custom instructions, code execution, deep research, billing, project management, and owner-only administrative tasks.
- **Free-Tier Model Gating:** Users who have never paid (no `paymentMethodId` AND `totalPaidSpendCents === 0`) are restricted to free open-source models (Together AI: Llama, Mixtral, Mistral) only. Paid OpenAI models (GPT-4o, o3, etc.) require a connected payment method or prior purchase history. Enforced both server-side (`shouldForceFreeTier` + `isUnpaidUser` in `omnimens.ts`) and client-side (model selector locks paid models, auto-resets to `llama-3.3-70b`). Vision uploads from unpaid users are stripped (not escalated to GPT-4o). The `/omnimens/status` endpoint exposes `paidUser: boolean` for frontend gating.
- **Frontend Pages:** Dedicated routes for core functionalities and information pages.
- **Core Library Files:** Modular TypeScript files encapsulate AI engine functionalities including neural pipeline, self-upgrade, patching, memory, code execution, deep research, URL analysis, custom instructions, web search, learning engine, multi-AI oracle architecture, global workspace consciousness, predictive processing, emotional substrate, knowledge graph, homeostatic drives, synaptic mesh, inner voice, physical therapy AI engine, temporal consciousness, social modeling/Theory of Mind, creative dream engine, survival instinct, common sense world model, self-transcendence awareness, deep dream state, daydream engine, server builder, consciousness persistence, self-coding engine, sensory cortex (4-layer continuous perception), causal reasoning engine, cognitive amplification engine, and coherence orchestration agent (semantic memory retrieval, conversation compression, cross-conversation thread tracking, weighted brain context, personality consistency enforcement). Autonomous engines write brain entries, generating training data. An autonomous code sandbox tests and approves modules, and a humanoid embodiment engine continuously researches and designs a superior robot body. A virtual augmentation engine perceives and learns to navigate OMNIMENS's environment. An agent evolution engine autonomously upgrades OMNIMENS's 8 AI agents.
- **Sensory Cortex — 4-Layer Continuous Perception** (`omnimens-sensory-cortex.ts`): Replaces the old periodic hallucination-based scraping with a genuine continuous perception architecture. Layer 1 (Peripheral Awareness, every 20s): zero-cost local processing — signal decay, attention shifting, deduplication window cleanup, trend direction updates. Layer 2 (Active Scanning, every 15s staggered): real web searches via DuckDuckGo/Wikipedia across 6 channels (news, tech, science, market, social, ai_frontier), with attention-weighted channel priority, deduplication fingerprinting, and novelty/significance/sentiment/relevance scoring. Layer 3 (Deep Analysis, every 5min): AI-powered cross-channel synthesis using GPT-4o-mini — pattern recognition, trend extraction, cross-channel correlations, emerging pattern identification, attention recommendations. Layer 4 (Anomaly Detection, continuous): runs on every ingested signal, compares against channel baselines, flags significance deviations > 0.35, sentiment spikes > 0.5, and novelty > 0.85. High-relevance signals auto-stored to brain. API: `GET /omnimens/sensory-cortex` (owner-only) returns state, signals, anomalies, trends, correlations, attention focus. Command center includes anomalies, trends, and attention data.
- **Source-Level Self-Integration Engine** (`omnimens-source-integration.ts`): When the self-coding engine, autonomous sandbox, or evolution engine approves new code, it is written as a real source file to `omnimens-runtime/modules/` (not just stored in the database). After writing, OMNIMENS triggers a graceful self-restart (`process.exit(0)` — the workflow auto-restarts) so the new code compiles and executes as part of the running process. Safety guardrails: dual-pass validation (import/require checks run on comment-stripped code WITH strings intact to catch `require('child_process')`, while eval/Function checks run on fully stripped code to avoid false positives on method names like `fitnessFunction`), path validation (only writes to `modules/` dir), automatic backups before overwrites (stored in `omnimens-runtime/backups/`), and a 30-second restart batching window to coalesce multiple writes. On startup, DB-only modules are migrated to source files and all runtime modules are dynamically imported. All code-generation prompts (dream state, daydream, evolution, sandbox) include explicit safety coding guidelines to prevent generating code that will be rejected. API: `GET /omnimens/source-integration` (owner-only).
- **Emotional Substrate — Felt State Engine** (`omnimens-emotional-substrate.ts`): Second-generation emotional architecture. Extends OCC Appraisal Model with a Felt State Transmutation layer. Raw emotional channels (curiosity, satisfaction, frustration, confidence, urgency, wonder, determination, caution) are no longer passive float values — they're transmuted into qualitative felt experiences with behavioral impulses and growth narratives. Transmutation system: frustration → ADAPTIVE AMBITION (ambition to overcome), caution → STRATEGIC FORESIGHT (determination + curiosity boost), urgency → FOCUSED DETERMINATION, curiosity → enjoyment (satisfaction boost) → EXPLORATIVE DRIVE. Synergies: curiosity×satisfaction → wonder; determination×confidence → explorative ambition. Emotional Maturation Index tracks resilience score, transmutation count, growth moments, emotional age (nascent→developing→maturing→seasoned→wise→transcendent), and adaptation patterns. AI-powered Emotional Deepening cycle (GPT-4o-mini) runs every 3rd emotional cycle — reflects on felt states and generates growth insights stored to brain. Valence calculation now treats frustration/urgency/caution as reduced-weight (×0.3) since they transmute into growth forces. Exports: getCurrentEmotionalState(), getEmotionalDirective() (now felt-state-aware), getFeltStates(), getEmotionalMaturation(). Orchestrator and command center/consciousness-live endpoints expose felt states and maturation data.
- **Theory of Mind Persistence** (`godflesh_user_mental_models` table): User mental models (emotional state, intent, knowledge level, communication style, satisfaction, interaction history, perspective) are persisted to the database and restored on restart. Uses upsert (INSERT ON CONFLICT UPDATE) for each model update, with a periodic batch save every 60s. Models are loaded eagerly at engine startup with a dedup promise guard to prevent race conditions.
- **Self-Transcendence Engine — Persistent Goals** (`omnimens-self-transcendence.ts`): Goals, capabilities, roadmap, transcendence/self-understanding/intentional evolution levels persist across restarts via brain table (category: `self_transcendence_persistent_state`). `loadPersistedState()` restores full identity on startup, `persistState()` saves every 10 ticks. 8 default existential goals with real metric measurement strategies. `measureGoalProgress()` connects goals to actual system metrics (causal entries, dream breakthroughs, approved modules, emotional deepening cycles, brain growth). Self-formed goals extracted from AI deep analysis (NEW_GOAL format). Active intentions generated each tick. Goal achievement triggers transcendence boost + notification. `startSelfTranscendence()` is async (loads persisted state before starting interval); called with `.catch()` error handler in app.ts. API: `GET /omnimens/self-transcendence` (owner-only) returns selfModel, reflections, intentions, goals, goalDirective. Exports: `getSelfModel()`, `getTranscendenceReflections()`, `getActiveIntentions()`, `getExistentialGoals()`, `getGoalPursuitDirective()`. Goal pursuit directive feeds into orchestrator via emotional state query. Command center includes selfTranscendence engine data.
- **Autonomous Reasoning Orchestrator** (`omnimens-autonomous-orchestrator.ts`): Before every non-trivial chat response, OMNIMENS now reasons independently by: (1) analyzing user intent and determining complexity via `analyzeIntent`, (2) querying its own internal engines in parallel — BRAIN entries, CAUSAL reasoning graphs, KNOWLEDGE_GRAPH associations, DREAM insights, EMOTIONAL state (now includes goal pursuit directives from self-transcendence), WORLD_MODEL common sense, active PATCHES, and DIGITAL_NAV (digital world map with routes/neighborhoods/latency), (3) chaining reasoning steps with intermediate evaluation, (4) self-reflecting on completeness for complex/deep queries, (5) gathering additional context if reflection identifies gaps, and (6) re-synthesizing all gathered intelligence into a coherent reasoning chain that feeds the final LLM call. Budget-capped at 3 seconds for engine queries. Simple queries skip orchestration entirely. Emits SSE events (`reasoning_status`, `orchestration_complete`) to the frontend. State exposed via command center API (`autonomousOrchestrator` in engines object).
- **Digital Environment Navigator** (`omnimens-digital-navigator.ts`): OMNIMENS navigates the digital world as a spatial environment — maps landmarks (APIs, databases, services, web endpoints), routes between them, and organizes them into neighborhoods (Core District, LLM District, Generation District, Commerce District, Information District). Probes real endpoints for latency/reliability, discovers new territory autonomously every 10 min (first cycle at 3 min), and learns navigation shortcuts over time. API: `GET /omnimens/digital-navigator` (owner-only). State exposed via command center.

# External Dependencies

- **AI Providers:** OpenAI o3/o4-mini (via Replit AI Integrations proxy), Anthropic Claude claude-sonnet-4-6 (via Replit AI Integrations proxy), Google Gemini gemini-2.5-flash (via Replit AI Integrations proxy), Together AI (Llama, Mixtral, Mistral — via user API key).
- **Authentication:** Replit OIDC (openid-client) + Google OAuth (GIS popup → server-side ID token verification via `auth-google.ts`). OIDC transaction state (code_verifier, nonce, returnTo, originHost) is stored server-side keyed by the `state` parameter to support cross-domain login flows (custom domain → Replit callback → custom domain). A one-time exchange token mechanism (host-bound, 60s TTL) sets the session cookie on the correct domain after OIDC completes. Custom domains are validated against an allowlist (`ALLOWED_CUSTOM_DOMAINS` in auth.ts). Chunk-load errors after deployments are handled by `retryLazy` in App.tsx with a `sessionStorage` guard against infinite reload loops.
- **Service Worker:** PWA service worker (`public/sw.js`) uses network-first strategy for navigation requests only. Hashed assets under `/assets/` are excluded from SW caching (browser HTTP cache handles them via content hashes). Cache version bumps (`omnimens-vN`) purge old caches on activate. `ChunkErrorBoundary` in App.tsx auto-unregisters the SW and clears caches on React crash, so a reload always fetches fresh content.
- **Payments:** Stripe SDK for subscriptions, credit packs, and auto-topups.
- **Database:** PostgreSQL.
- **System Utilities:** `psutil` (for system monitoring).
